# Sift Engineering Instructions

Sift is a **local-first Electron desktop app** that indexes video clips in place. It is
built with **electron-vite 5** across three isolated processes, written in **TypeScript strict
mode**, with a **Vue 3.5** renderer using `<script setup>` and module-scope composables for
state. There is no router, no Pinia, no server, no network, and no database — clip metadata
lives in one debounced JSON document, and the media pipeline is a bounded queue around a
bundled ffmpeg.

The defining constraint: **this app runs while the user is playing a game.** Every design
decision — bounded concurrency, below-normal process priority, batched IPC, a windowed grid,
transform-only animation — exists to keep Sift from stealing frames. Do not regress it.

---

## Tech Stack

- **Shell:** Electron 44
- **Build:** electron-vite 5 + Vite 7 (`electron.vite.config.ts` configures all three targets)
- **Language:** TypeScript 5.9, strict mode, ESM (`"type": "module"`)
- **UI:** Vue 3.5 (`<script setup lang="ts">`), no router, no store library
- **Component kit:** Nuxt UI v4, auto-imported, themed onto the app tokens (see `sift-nuxt-ui`)
- **Styling:** Tailwind v4 (supplied by the Nuxt UI plugin) + scoped CSS against custom properties
- **Motion:** GSAP, motion-v, ogl (see `sift-motion`)
- **Media:** `ffmpeg-static` + `ffprobe-static`, spawned as child processes
- **Watching:** chokidar 5
- **Packaging:** electron-builder 26
- **Package manager:** npm

Path aliases (configured per-target in `electron.vite.config.ts`):

- `@shared/*` — available in **all three** processes
- `@/*` — `src/renderer/src/*`, **renderer only**

Never reach across a process boundary with a relative path (`../../main/lib/...`). If two
processes need the same thing, it belongs in `src/shared/`.

## Process Boundaries

This is the rule that matters most. Getting it wrong is either a security hole or a stall.

| Concern                                              | Lives in   |
| ---------------------------------------------------- | ---------- |
| Filesystem, `child_process`, `shell`, `dialog`, `app` | **main**   |
| Persisted state, scanning, watching, ffmpeg           | **main**   |
| Channel wiring and nothing else                       | **preload** |
| Types shared by two or more processes                 | **shared** |
| Rendering, view state, formatting, input handling     | **renderer** |

- The renderer has `nodeIntegration: false` and `contextIsolation: true`. It cannot import
  `node:fs`, `electron`, or anything Node — **do not try**. If the renderer needs data from
  disk, add an IPC method.
- The preload script is a **wiring layer**. It maps `window.api.x.y()` to
  `ipcRenderer.invoke('x:y')` and nothing more. No business logic, no validation, no caching,
  no `fs` access. Its only judgement call today is normalising `undefined` to `''`.
- The main process never reaches into renderer state. It emits events; the renderer reacts.
- Long or blocking work never runs on the main process's event loop. Spawn a child process
  (ffmpeg) or use async `node:fs/promises`. Never `readFileSync` a video.

## The IPC Contract

Channels are named `domain:action` in kebab-case: `library:add-folder`, `clip:rename`,
`window:toggle-maximize`. Renderer → main is always `invoke`/`handle` (request/response).
Main → renderer is always `webContents.send` with a payload typed in `EventMap`.

### Adding or changing an API method

A new capability is a **four-file change, in this order**:

1. `src/shared/types.ts` — add or extend the domain types and, for a push event, add the
   channel to `EventMap`.
2. `src/shared/api.ts` — declare the method on the `Api` interface. This is the contract.
3. `src/preload/index.ts` — wire it to a channel. TypeScript will fail here if the shape
   drifts from `Api`, which is the point.
4. `src/main/ipc.ts` — register the `ipcMain.handle`, delegating to a `Library` method.

Never add an `ipcMain.handle` outside `ipc.ts`, and never call `ipcRenderer` outside the
preload script.

### Validating IPC input

Everything arriving from the renderer is untrusted input, even though we wrote the renderer.
`ipc.ts` coerces with a `str()` helper before passing anything on:

```ts
const str = (v: unknown): string => (typeof v === 'string' ? v : '')

ipcMain.handle('clip:rename', (_e, id, name) => library.renameClip(str(id), str(name)))
```

Follow the same pattern for new handlers — coerce or reject at the boundary, never trust the
declared parameter type. Path arguments get special care: resolve them against a known root
and reject anything that escapes it. `library.ts` already rejects names containing
`[<>:"/\|?*]` before touching the filesystem.

### Return shapes

- Actions return `ActionResult` (`{ ok, error? }`), optionally widened
  (`ActionResult & { clip?: Clip }`). **Never throw across IPC** — a rejected `invoke`
  surfaces in the renderer as an opaque `Error` with a mangled message.
- Handle the failure in main, return `{ ok: false, error: 'human readable reason' }`, and let
  the renderer decide how to present it (usually `toast('error', …)`).

### Events, not chatter

`Library` batches `clips:added` / `clips:updated` / `clips:removed` on a **150ms flush timer**
(`FLUSH_MS`), in chunks of `ADD_BATCH` (40). A 3,000-clip scan becomes a few dozen messages,
not 3,000. Any new high-frequency signal must join that batching path — do not add a per-item
`webContents.send`.

## Renderer State

There is **no state-management library**. Composables in `src/renderer/src/composables/` export
module-scope `ref`s and `computed`s, so importing one is importing shared state. This is
deliberate: a single-window app with one library does not need a store abstraction.

```ts
// composables/useLibrary.ts — module scope, shared by every importer
export const folders = ref<LibraryFolder[]>([])
export const settings = ref<Settings>({ ...DEFAULT_SETTINGS })
export const selectedGame = ref<string | null>(null)
```

Rules:

- **One owner per concern.** `useLibrary` owns clips/folders/settings/scan, `usePlayer` the
  player, `useToasts` the notification queue, `useDialogs` modal promises, `useMotion` the
  motion gate, `useVirtualGrid` grid geometry. Add state to the owner; do not duplicate it in a
  component. (There is no `useContextMenu` — the right-click menu is a `UContextMenu` around
  each card, with its items built in `ClipGrid.vue`.)
- **Components are presentational.** They read composable state and call composable actions.
  A component should not call `window.api` directly — go through the composable that owns the
  domain, so optimistic updates and toasts stay in one place.
- **Actions live beside the state** (`addFolder`, `renameClip`, `deleteClip`, `updateSettings`).
  They call `window.api`, apply the optimistic local change, and raise a toast on failure.
- Use `defineProps`/`defineEmits` for parent → child data. Reserve `provide`/`inject` for
  genuinely tree-scoped context.

### The `Map` + version counter

Clips are held in a plain `Map<string, Clip>` **outside** Vue's reactivity, with a `version`
ref bumped on every mutation:

```ts
const clipsById = new Map<string, Clip>()
const version = ref(0)

export const allClips = computed<Clip[]>(() => {
  void version.value          // the dependency
  return Array.from(clipsById.values())
})
```

This avoids deep-proxying thousands of objects. **Preserve it.** When you mutate:

- Always `version.value++` after touching the Map, or nothing re-renders.
- Always `void version.value` at the top of any computed that reads the Map.
- Replace clip records with **fresh object references** (`clipsById.set(id, { ...c, ...patch })`)
  rather than mutating in place, so `:key`-ed children see a changed prop.
- Do not wrap the Map in `reactive()` or `ref()` "to be safe" — that reintroduces exactly the
  cost this pattern removes.

## Vue Conventions

- `<script setup lang="ts">` only. No Options API, no `defineComponent`, no class components.
- **Nuxt UI `U*` components are auto-imported — do not import them.** App components
  (`ClipCard`, `Sidebar`, `bits/*`) *are* imported explicitly, which is how a reader tells app
  code from library code at a glance. Keep both halves of that convention.
- Lazy-load a component whose dependency is heavy and conditionally rendered.
  `LibraryView` does this for the WebGL hero so `ogl` never enters the main chunk:
  `const Aurora = defineAsyncComponent(() => import('./bits/Aurora.vue'))`.
- Type props with the generic form and `withDefaults`:

```ts
const props = withDefaults(defineProps<{ name: string; size?: number }>(), { size: 18 })
```

- Keep components single-purpose. When a component passes ~300 lines, split the presentational
  part out or move logic into a composable. `PlayerOverlay.vue` is the outlier, not the model.
- Prefer `computed` over `watch`. Reserve `watch`/`watchEffect` for genuine side effects
  (DOM classes, `api` subscriptions, timers).
- **Every** listener, timer, observer, `requestAnimationFrame` loop, and GSAP tween registered
  in `onMounted` must be torn down in `onBeforeUnmount`. `window.api.on()` returns its own
  unsubscribe function — call it.
- Use `v-memo`/`shallowRef` only with a measured reason; do not sprinkle them.
- Wrap async work started in a component so a late resolution cannot touch an unmounted tree.

## TypeScript

- Strict mode, everywhere. **No `any`, no `@ts-ignore`, no non-null `!` to silence an error.**
- Annotate exported function return types explicitly (the codebase already does: `: void`,
  `: Promise<Clip | null>`).
- Prefer union types over enums (`type SortBy = 'newest' | 'oldest' | …`).
- Domain types live in `@shared/types` when more than one process sees them; renderer-only
  view types (`GameSummary`, `Section`, `GridRow`) live beside the composable that owns them.
- Use discriminated unions for variant shapes — `GridRow` (`kind: 'header' | 'cards'`) and the
  dialog state (`kind: 'confirm' | 'prompt'`) are the house style.
- Narrow unknown input with a type guard at the boundary; do not cast it.
- Two tsconfigs cover the codebase: `tsconfig.node.json` (main + preload + shared) and
  `tsconfig.web.json` (renderer + shared). Put a new file where it can actually see its APIs.
- `tsconfig.web.json` also includes `src/renderer/*.d.ts`, which is how the generated
  `auto-imports.d.ts` and `components.d.ts` reach the type checker. Both are **generated** —
  never hand-edit them, and never commit a fix into them. If a `U*` component or a Nuxt UI
  composable types as `any`, the dts is stale: restart `npm run dev`.

## Main-Process Rules

### Child processes (ffmpeg / ffprobe)

- Spawn only through the helpers in `lib/media.ts`. Every job must keep:
  - `windowsHide: true` — no console flash
  - `setPriority(pid, PRIORITY_BELOW_NORMAL)` — the game wins
  - `-threads 1` on ffmpeg
  - a `JOB_TIMEOUT_MS` kill timer (60s) that is always cleared
  - `stdio: ['ignore', 'pipe', 'pipe']` with stderr drained (never left to fill a pipe buffer)
- Concurrency is bounded by `MediaQueue` and defaults to **2** (`Settings.concurrency`). Do not
  add a parallel spawn path outside the queue.
- Prefer cheap ffmpeg strategies: sprite strips use keyframe seeks stitched with `hstack`
  rather than decoding whole files. Do not replace one with a full decode.
- Binaries resolve through `lib/paths.ts`, which must handle both dev and the ASAR-unpacked
  installer layout. Never hardcode a path into `node_modules`.

### Persistence

- `Store` is one JSON document written with **debounced (800ms), atomic (write-temp-then-rename)**
  saves. Keep both properties: a torn `library.json` loses the user's entire index.
- `load()` tolerates a missing or corrupt file and starts clean. Any new field must have a
  default in `DEFAULT_SETTINGS` and survive an old document (`{ ...DEFAULT_SETTINGS, ...raw }`).
- `LibraryData.version` exists for migrations. Bump it and migrate explicitly when the shape
  changes — do not silently reinterpret old data.
- **Never copy, move, or modify a user's video file** except for the two explicit actions:
  rename (`fs.rename` in place) and delete (`shell.trashItem` → Recycle Bin, never `unlink`).
  Removing a folder from the library must leave the files untouched.

### Lifecycle

- Single-instance lock is required; `second-instance` focuses the existing window.
- `before-quit` is intercepted once (`shuttingDown` guard) so `library.shutdown()` can flush
  the store and stop watchers before the app exits. Any new resource that needs draining goes
  into `shutdown()`.
- Guard every `webContents.send` with `!win.isDestroyed()`.

## Security

The renderer loads only local content, but the rules still hold:

- `contextIsolation: true`, `nodeIntegration: false` — never relax either.
- Exactly one `contextBridge.exposeInMainWorld` call, exposing the typed `Api` object. Never
  expose `ipcRenderer`, a generic `invoke(channel, …)`, or any Node module.
- `setWindowOpenHandler` denies all popups and hands `http(s)` URLs to `shell.openExternal`.
  Keep the scheme allowlist — never pass an arbitrary URL to `openExternal`.
- The `clip://` protocol handler must resolve an id to a path **through the library index**,
  never by joining user input onto a base directory. Reject anything that resolves outside a
  registered folder.
- `src/renderer/index.html` carries a **Content-Security-Policy meta tag** that is the last line
  of defence: `default-src 'self'`, `script-src 'self'`, `img-src 'self' clip: data: blob:`,
  `media-src clip: blob:`, `font-src 'self' data:`, and `connect-src` limited to `'self'` plus
  localhost (for the dev server's websocket). `style-src` allows `'unsafe-inline'` because Vue
  scoped styles and Nuxt UI need it. **Adding a remote asset, font, or API call means widening
  this policy — which is the signal to stop and ask, not to edit the tag.**
- No `eval`, no `new Function`, no remote script or font, no `webSecurity: false`.
- Nothing in this app talks to the network. If a change would introduce a network call, stop
  and raise it — "local-first" is a product promise, not an implementation detail.

## Performance Rules

These are load-bearing. Read the "Efficiency notes" in `README.md` before changing any of them.

- **The grid is windowed.** `useVirtualGrid` computes row geometry from scroll position and
  container size; only visible rows plus a 420px overscan exist in the DOM. Never render the
  full clip list, and never add a CSS layout change the composable does not model.
- **Clips stay out of the reactivity graph** (the Map + version counter above).
- **IPC is batched** at 150ms.
- **Media jobs are bounded and de-prioritised.**
- Video streams through `clip://` with HTTP range support; read streams are destroyed the
  moment Chromium abandons a request. Do not buffer a whole file into memory.
- Animate transform and opacity only. Never animate layout properties on repeated elements.
- Thumbnails and sprite strips are cached in `%APPDATA%/sift/thumbs` and generated once.
  Do not regenerate on every scan; check for the artifact first.
- Timers that tick forever (the `now` ref updates every 60s to keep relative labels honest)
  must stay cheap and must not trigger a full list rebuild.

When you touch a hot path, say what got faster and how you know.

## Error Handling

- IPC handlers return `{ ok: false, error }`; they do not throw.
- Renderer actions surface failures with `toast('error', title, message)` from `useToasts`.
  Never `alert()`, never `console.log` an error and move on silently.
- `useToasts` is a **queue, not a renderer**. Nuxt UI's `useToast()` needs a component setup
  context, which module-scope composables do not have, so `toast()` pushes onto `pending` and
  `ToastBridge.vue` (mounted inside `<UApp>`) forwards each item to the real toaster. Call
  `toast()` from app code; call `useToast()` only inside `ToastBridge`.
- Use the shared `confirm()` / `prompt()` from `useDialogs` for destructive or input flows —
  they return promises and render through the single `UModal` in `DialogHost`. Never use the
  native `window.confirm` / `window.prompt`.
- A missing drive is not an error state to crash on: folders carry `available: false` and their
  clips are **kept, not dropped**. Preserve that behaviour.
- A failed probe sets `probeState: 'failed'` on the clip rather than removing it.
- Swallow an exception only where the failure is genuinely non-fatal, and say so in a comment —
  as `lowerPriority()` and `Store.load()` already do.

## Comments and Documentation

The codebase is lightly but deliberately commented. Match it:

- JSDoc on exported types and functions whose contract is not obvious from the signature —
  especially where a field's meaning is non-obvious (`/** Best-effort recording time: parsed
  from the file name, else birthtime/mtime. */`).
- A short block comment above a non-obvious mechanism explaining **why**, not what — the Map +
  version counter, the batching window, the keyframe-seek sprite strategy.
- Files in `components/bits/` carry a header naming the Vue Bits source URL and every local
  adaptation. Keep it accurate when you edit one.
- Do not add narrating comments to self-evident code, and do not leave `console.log` in a commit.

## npm

Always use **npm** — never pnpm or yarn. `package-lock.json` is committed; do not hand-edit it.

```bash
npm install                 # dependencies + electron-builder install-app-deps
npm run dev                 # electron-vite dev
npm run typecheck           # node + web, both must pass
npm run build               # typecheck + build
npm run build:win           # Windows installer into dist/
npm run build:unpack        # unpacked folder for a quick smoke test
```

Native or binary-bearing dependencies (`ffmpeg-static`, `ffprobe-static`) must be listed in
`dependencies`, not `devDependencies`, and unpacked from the ASAR via `electron-builder.yml`.
Renderer-only libraries belong in `devDependencies` — Vite bundles them.

## Verification

After any change, from the project root:

```bash
npm run typecheck
```

Both `typecheck:node` and `typecheck:web` must pass — a preload/`Api` mismatch only shows up
in one of them. For anything that touches the media pipeline, protocol, or store, also run
`npm run build` before calling it done.

To confirm behaviour in the running app, ask the user to reload (`Ctrl+R`) or restart
`npm run dev`, and describe what to look for. **Do not drive the user's live application
window with synthetic input.**

To test against a throwaway library without disturbing the user's real one, launch with an
isolated profile — it gets its own `library.json`, thumbnail cache, and single-instance lock,
and the window title is marked `Sift (dev profile)`:

```bash
SIFT_USER_DATA=./.tmp-profile npm run dev
```

## Do Nots

- ❌ Do not use `any`, `@ts-ignore`, or `!` to silence a type error
- ❌ Do not hand-edit `auto-imports.d.ts` or `components.d.ts` — they are generated
- ❌ Do not call Nuxt UI's `useToast()` outside `ToastBridge.vue` — app code calls `toast()`
- ❌ Do not import Node modules or `electron` in the renderer
- ❌ Do not put logic, validation, or `fs` access in the preload script
- ❌ Do not register `ipcMain.handle` outside `src/main/ipc.ts`
- ❌ Do not call `ipcRenderer` outside the preload script
- ❌ Do not call `window.api` directly from a component — go through its composable
- ❌ Do not throw across IPC — return `{ ok: false, error }`
- ❌ Do not trust IPC arguments; coerce and validate at the boundary
- ❌ Do not mutate the clip `Map` without bumping `version`
- ❌ Do not make the clip `Map` reactive
- ❌ Do not render the full clip list — the grid is windowed
- ❌ Do not send per-item IPC messages; join the 150ms batch
- ❌ Do not spawn ffmpeg outside `MediaQueue`, or at normal priority, or without a timeout
- ❌ Do not `unlink` a user's file — use `shell.trashItem`
- ❌ Do not do blocking or sync I/O on the main process event loop
- ❌ Do not relax `contextIsolation`, `nodeIntegration`, or `webSecurity`
- ❌ Do not add a network request, remote font, or CDN asset
- ❌ Do not use `npm`-adjacent tools (pnpm, yarn) or hand-edit the lockfile
- ❌ Do not add a state-management library or a router
- ❌ Do not leave `console.log` in committed code
